# docs/

Planes de implementación del proyecto, uno por fase o por feature.

**Cualquier plan que se proponga antes de escribir código va acá**, como archivo
Markdown versionado — no en un chat ni en notas sueltas. El plan se commitea
junto con el trabajo que describe, para que en la revisión se vea el porqué de
los cambios y no solo el diff.

- Nombre sugerido: `plan-<fase>-<feature>.md`, por ejemplo
  `plan-fase1-crud-noticias.md`.
- El orden de las fases y sus checkpoints están en `../README.md`.
- Un plan cumplido puede borrarse: el historial de Git lo conserva.
